# 社交媒体内容生产 · 需求对齐

状态：决策已逐项确认（2026-11-04）；F1–F11 代码与自动化测试已落地，真实 DSH Desktop 安装/槽位验证与真实模型 key 联调待做。
基线：[`需求规格说明书.md`](../需求规格说明书.md) v0.3。本稿记录本轮新增与变更；与基线冲突时，以本稿为准。

## 1. 一句话

把 `content-studio` 做成一个 DSH 插件：运营在左侧栏打开「内容生产」总控台，建批次后由 Harness 流水线产出视频，ChatGPT（OpenAI 兼容接口）出全部文案，自动校验，人工审核或自动放行，导出发布包，并在页面里看到生产日志。本期不做平台分发。

## 2. 角色

- **运营同事**：安装插件、填自己的模型 key、建批次、审核、导出。
- **开发/管理员**：维护插件与索引源、平台预设、升级。
- 单机单用户；不建账号与权限体系。

## 3. 端到端流程

1. **安装**：DSH 桌面版「发现」添加索引源 → 安装/更新 → 左侧栏出现「内容生产」。
2. **首次打开**：就绪检查（ffmpeg、文案/配音/视频 key、素材库）。
3. **建批次**：主题、条数、素材目录、平台、发布起点与间隔、审核模式、成本上限；平台预设带出规格；创建前显示预检摘要。
4. **生产**：文案 → 配音 → 字幕 → 画面 → 剪辑方案 → 渲染 → 封面 → 校验。
5. **校验**：现有 18 项 + 平台规格硬校验；失败自动重试 1 次，仍失败告警。
6. **审核**：`reviewMode=required` 的批次进入审核台；`auto` 直接进入待发布。
7. **导出**：一条或整批导出发布包（成片 + 三尺寸封面 + 文案）。
8. **日志**：批次时间线、条目步骤耗时、失败原始错误。
9. **成本**：80% 提示，100% 暂停；提高上限后继续。

## 4. 功能清单

### F1 安装与入口

- 私有 GitHub 仓库；公开 metadata 索引；DSH 官方「发现」安装/更新。
- 客户端注册 `main` 主面板 + `sidebar.panellist` 图标，不再注册 `settings.section`。
- 验收：干净电脑添加索引源 → 点安装 → 左侧栏出现「内容生产」→ 点开总控台。

### F2 首次使用就绪检查

- ffmpeg、llm/tts/video key、素材库逐项检查；缺项给「去配置」。
- 验收：缺 key 时能直达「设置」页签；补齐后全绿。

### F3 批次创建

- 字段：主题、条数、素材目录（可多选）、平台（单选）、发布起点、发布间隔、审核模式、成本上限；沿用画幅、目标时长、镜头数、音色、转场、并发。
- 单页表单分三组：内容规格 / 发布设置 / 成本与审核；底部预检摘要。
- 验收：创建后批次列表可见；预检能提示缺模型、素材不足、磁盘不足。

### F4 平台预设

- 首批抖音、小红书、视频号；v1 复用已验证默认值（9:16、目标 26s、封面三尺寸），平台差异先只影响标题字数提示；批次可覆盖。
- 验收：切换平台带出默认值；覆盖后按覆盖值生产。

### F5 生产流水线

- 复用现有 8 步；ChatGPT（OpenAI 兼容）生成口播稿、标题、简介、标签、封面主副文案、底图提示词；封面底图可选用生图模型，本地叠中文；无生图时纯色底图并标 `degraded`。
- 验收：3 条全链路产出；断点续跑、并发与素材去重保持。

### F6 校验

- 18 项 + 平台硬规格；文件与规格失败阻断，文案问题警告；报告区分 blocking / warning。
- 验收：故意破坏画幅、时长、封面能阻断；标题过长只警告。

### F7 审核

- 批次级 `reviewMode`，默认 `required`；通过、驳回、局部重做、批量通过、撤回；键盘快捷键保留。
- 验收：`required` 批次进入审核台；`auto` 批次不进审核台，直接待发布。

### F8 导出

- 每条一个 zip：`master.mp4`、封面三尺寸、`文案.txt` / `copy.json`、校验报告；整批可批量导出。
- 验收：导出包可解压，内容完整。

### F9 日志与告警

- 批次时间线、条目步骤与耗时、失败原始错误；失败在批次列表红标 + 顶部汇总；自动重试 1 次。
- 验收：制造一次失败，能看到重试记录、最终错误和原始日志。

### F10 成本护栏

- 用量记账已有；新增批次成本上限、80% 提示、100% 暂停；暂停原因可见，提高上限后继续。
- 验收：低上限批次在 100% 暂停，不继续消耗。

### F11 分发与升级

- 私有 GitHub 仓库；公开 `index.json`（GitHub Pages）；索引指向 tag / commit；同事点更新。
- 验收：改索引 commit 后，已安装插件出现更新并可升级，数据保留。

## 5. 数据与状态

批次配置新增：

```json
{
  "platform": "douyin",
  "publishStartAt": "2026-11-05T18:00:00+08:00",
  "publishIntervalMinutes": 1440,
  "reviewMode": "required",
  "costCap": 30
}
```

- 批次状态：`queued / running / paused / review / done / cancelled / failed`；暂停增加 `pauseReason`（`user` / `cost_cap`）。
- 条目状态：`pending / running / review_pending / approved / rejected / failed / cancelled`。`auto` 模式下从 `running` 直接到 `approved`，跳过 `review_pending`。
- 校验结果区分 blocking 与 warning。
- 导出记录 `exports[]`（时间、路径、条目数）。
- 生产日志沿用 `batch.log` / `item.log`；新增页面读取接口。

## 6. 技术形态

| 项 | 决定 |
|---|---|
| 宿主 | DSH Desktop NEXT 2.0.21 / dsh 0.2.1-rc.4，`engines.dsh` 锁 `>=0.2.1-rc.4 <0.3.0` |
| 形态 | 单个 DSH bundle：Host `index.js` + Client `client.js`（lazy-CJS，无需构建步骤） |
| 入口 | `main` 主面板 + `sidebar.panellist` 图标；不注册 `settings.section` |
| 分发 | 私有 GitHub 仓库 + 公开 metadata 索引；官方「发现」安装 |
| ffmpeg | `@ffmpeg-installer/ffmpeg` + `@ffprobe-installer/ffprobe`，解析顺序优先显式配置与 PATH |
| 数据 | `~/.content-studio` |
| 不做 | 独立桌面端、独立网页端、公开 npm、公共市场目录 |

## 7. 本期不做

- 平台上传、分发、发布回执、发布日志（P5/P6）。
- 一条内容生成多平台变体。
- 独立 worker 进程（关掉 DSH 停止渲染，重开续跑）——见 ADR 0006。
- 团队账号、权限、多人协作。
- `api.log` / `render.log` 的完整采集；保留 `batch.log` / `item.log`。
- 平台 API 联调；本期用真实模型 key 生产，但不调用平台发布 API。

## 8. 验收标准

在一台干净的 Windows 电脑 + DSH Desktop 0.2.1-rc.4 上：

1. 添加索引源 → 安装 → 左侧栏出现「内容生产」。
2. 填自己的 key → 就绪检查全绿。
3. 建 3 条抖音批次，默认审核；3/3 产出，校验通过。
4. 审核通过 / 驳回 / 局部重做；`auto` 批次直接待发布。
5. 导出 3 个发布包，内容完整。
6. 制造一次失败：自动重试 1 次 → 红标 → 原始错误可见。
7. 成本上限 80% 提示、100% 暂停。
8. 生产日志能定位到条目、步骤与错误。
9. 现有测试 + 新增测试全部通过（当前 454 项）。

## 9. 开放实现项

- 索引仓库 URL 与 GitHub Pages 地址（部署时确定）。
- 包名已定为 `dsh-content-factory`。
- ffmpeg 4.x 的渲染回归结果。
- DSH 桌面版里 `webServer` 路由与客户端 slot 的可用性（安装后第一件事验证）。
- 平台预设的具体数值（v1 复用现有默认值）。
